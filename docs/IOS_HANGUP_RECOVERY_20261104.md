# SkySIM 挂断待确认阻塞恢复（2026-11-04）

用户反馈手机 App 拨号与接听不可操作。通过 Workbench 只读核对生产环境：两块模块在线，control、telephony 和 audio 均就绪，快照与目录的连接、启动和后端代次一致，App 实际 Swift 解码器可解析实时响应。当前已配对客户端的 EG25 最近一条通话命令为 2026-11-03 10:06:33 UTC 的 `call.hangup`，状态 `outcome_unknown`，无回执；没有活动通话所有权保留项。本轮未读取真实号码或短信内容，也未发送真实通话命令。

## 根因与修复

`CloudV2Model.canAct` 在有待确认命令时为 false，导致拨号禁用、接听入口不提交请求。原逻辑仅在挂断已有终态回执、同一连接/启动/后端代次且快照明确显示目标通话 disconnected 时清除 pending；丢失回执或随后更新 Engine，可能永久阻塞。旧通话所有权虽可随运行代次变化释放，pending 并未随之恢复。这个缺陷已由重启恢复测试复现；尚未直接读取用户手机 pending 文件，因此现场原因以云端证据和复现为依据。

新增挂断观察恢复：同一身份、模块及传输路径下，当前在线目录与新鲜快照一致，control.ready 与 calls.available 均为 true，且旧运行代次已被替换，或目标通话在同一运行代次明确 disconnected 时，持久清除旧挂断 pending。连接代次变化但运行实例和通话身份相同也可恢复。此处确认的是旧通话不再需要挂断，不伪造命令执行回执，也不修改云端历史。

回执请求或提交仍在进行时不清除，避免迟到结果重新写回 pending；磁盘清除失败时继续阻塞并保留元数据。过期/未来/离线快照、目录不一致、不同身份或模块、仅断线重连、同一实例中目标通话缺失均不作为解除依据。未知拨号、接听、DTMF 和短信继续查询原回执，不自动重发。
