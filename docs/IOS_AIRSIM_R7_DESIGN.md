# AirSIM R7：原有界面的 v2 适配审核

2026-10-25。范围为 iPhone/iPad 主界面、设备连接、通话、短信、设置及 Watch 关联体验。目标是在原有视图中接入 ECS v2，保留云端 v1/v2 选择。本文件提供产品行为、视觉建议和验收标准；协议、后台生命周期和推送路由方案由主控确定，执行会话在主控确认后实施。

## 结论

保留原五标签导航、拨号盘、联系人、短信会话和全屏通话界面。当前 v2 独立三标签实验界面缺少最近通话、联系人和原有通知导航，不宜成为 R7 的产品入口。把模块选择放进原拨号页设备卡，把连接版本与配置放进原设置页；不同服务的历史和操作身份继续隔离。

原 UI 的系统 TabView、统一列表尺寸、联系人头像、带文字的连接状态和独立通话覆盖层可以继续使用。通讯录拒绝授权后的“前往系统设置”、短信清空确认、拨号删除键的无障碍说明也值得保留。R7 不需要重新设计一套视觉语言。

## 优先处理的适配缺口

### D01 · 高：切到 v2 后整套导航与交互改变

**证据。** AirSIMRouteView 按版本选择 CloudV2Host 或 LegacyAppHost。RootView 有拨号、最近、短信、联系人、设置五个标签，CloudV2View 只有模块与通话、短信、设置三个标签。系统 tel/im、短信通知打开会话和来电打开 App 的处理在 RootView 内。

**建议。** 保持五个标签的顺序、名称与原有视图。让 v2 使用原拨号盘、最近列表、联系人详情、短信列表/会话/编辑器及设置；服务版本不是另一款 App。复用视图时保留原服务身份，不能把旧通知按当前选择重新解释。

**验收。** v1/v2 均能从五个标签完成相同入口操作；联系人号码选择、最近回拨、系统拨号/短信入口和短信通知跳转均有明确结果。切换后不会混入另一服务历史，返回键不会打开旧服务的会话。已有 v1 安装仍保留原选择。

### D02 · 高：后台行为仍受前台实验契约限制

**证据。** CloudV2Model 在 background 停止轮询并启动本客户端通话的挂断清理；CloudV2View 明示后台来电不可用。V2Discovery 解码当前要求 apns 为 false。该行为符合 R5/R6，属于 R7 能力缺口，并非旧版实现错误。

**建议。** R7 来电沿用系统来电入口与原 ActiveCallView；从锁屏接听、切回 App、权限弹窗和主动挂断的状态应一致。普通离开 App 不应在支持后台通话的模式下表现为用户主动挂断。主控先确定推送、通话归属和生命周期契约，再替换实验说明；不能仅删掉限制文案。

**验收。** 前台、后台、锁屏及冷启动来电均能识别正确模块和通话；系统与 App 接听/拒接/结束不会出现双份通话。迟到的旧版本通知不会操作当前模块。凭据、服务推送或后台能力不可用时，在设置明确说明原因；“服务器连接成功”不显示为“后台来电已就绪”。真实 APNs/CallKit 结果由专门真机验收确认。

### D03 · 高：设备身份和可操作性缺少统一呈现

**证据。** 原拨号卡与引导使用 Android Agent、三星名称；v2 模块仅显示 module_id 前八位、在线与最近同步。v2 通话不可用提示把“不支持/未就绪”和“过期”合在一句，短信按钮禁用时没有对应原因。原首次引导和设置“关于”也固定为三星。

**建议。** 复用原设备卡，主行显示已有设备名称；无名称时使用模块类型与短标识，详情保留可区分的完整身份。副行显示当前连接版本和状态，模块选择沿用“全部设备”入口。根据实际原因分别呈现未配置、未选择、离线、状态待更新、能力不支持、凭据到期、结果待确认，并提供对应下一步。三星配对说明只出现在适用的连接流程。

**验收。** 未选模块不能误拨默认模块；模块离线、快照过期、语音不可用时，用户在拨号页就能理解不可用原因。切换设备后，拨号、短信、历史和状态都指向同一身份。无名称、长名称及无号码均有可读回退，不增加新的设备命名协议作为前提。

### D04 · 中：设置里的多个开关表达相互交叠

**证据。** AirSIMSettingsView 同时有“连接版本”三选项、“仅本地模式”和“远程通话与短信”；前两者都修改 router.choice，第三者修改 cloudModeEnabled。v2 设置则另有配置导入、连接和实验说明，并没有原外观选择。

**建议。** 原设置页保留一个明确的连接方式入口：仅本地 / 云端 v1 / 云端 v2。当前版本的配置紧邻显示；如仍保留独立远程开关，应说明它控制的能力，不让“已选择云端”被读成“已连上云端”。外观偏好保持跨版本一致。诊断原始字段放入诊断区域，常规设置使用用户可理解的状态和恢复动作。

**验收。** 活动通话或未确认操作期间，切换入口解释阻止原因；失败后仍显示原选择。配置到期能从当前状态直接到达更新入口。不会将 v1 Relay、三星配对、自检项目展示为 v2 必填项；云厂商不成为新的协议选择器。

### D05 · 中：通话控制不能按外观原样照搬

**证据。** ActiveCallView.connectedSurface 总是传 showsRecording: true；AppModel.toggleRecording 只接受 verifiedVoWLANAPI。云端独立通话时仍会提供一个无法执行的录音按钮。v2 现有控制与原控件可用条件也不同。

**建议。** 沿用原接听、拒接、静音、键盘、路由和挂断位置，按当前能力决定附加控件是否可用。无录音能力不提供可点录音按钮。通话状态与音频状态分别描述；控制提交中、结束中、结果待确认不显示成新的可拨号状态。

**验收。** 无本地 VoWLAN 路由时不出现可操作录音入口；v2 无该能力时行为一致。重复点接听/挂断不会生成第二个用户操作。实际音频路由与扬声器请求状态可区分，音频失败时仍可找到挂断。媒体性能和听感优化不属于本轮。

## 原界面中的明确问题

### D06 · 高：会话内回复失败会丢失正文

**证据。** MessageThreadView 点击发送先执行 reply = ""，再调用 sendSMS 并忽略 Bool 返回值；断网、无路由、验证失败均可到达失败分支。新建编辑器 MessageComposer 则只有成功后才关闭。

**建议。** 会话回复与新建编辑器采用一致的发送状态。保留失败正文和收件人；提交后结果未知时展示“结果待确认”，引导查询原操作，不能把再次点击变成隐式重发。不要在用户已输入下一条正文时用旧结果覆盖它。

**验收。** 无路由或拒绝发送后正文仍可编辑；发送中不能重复提交同一条；结果未知时保留原操作状态；成功清空的只是不再需要的已提交草稿。v2 字数限制在编辑区域提前显示，超限给出原因，发送状态不能被统一写成“已发送”或“已送达”。

### D07 · 高：清空短信忽略设备端失败

**证据。** MessagesView 确认删除后执行 try? await model.api.clearModuleSMS()，随后无条件 clearLocalMessages()。确认文字承诺删除本机和未交付模块短信；设备端失败时界面仍清空，后续同步可能重新出现消息。

**建议。** 删除范围与实际支持一致。执行失败保留记录并告知失败；如提供仅清除本机历史，独立命名并明确范围。v2 不存在相应能力时不调用旧端点，也不继承“模块短信已删除”的承诺。

**验收。** 模拟设备离线或删除接口失败后不会静默清掉全部记录；成功才呈现对应范围已清除。结果未知时不自动重发删除。取消确认不改变历史。

### D08 · 中：搜索无结果被误报为通讯录为空

**证据。** ContactsView 使用 filtered.isEmpty 直接呈现“通讯录为空”，即使系统联系人已加载且只是当前查询无匹配。

**建议。** 有查询时显示“没有匹配的联系人”，提供清除搜索；真实空通讯录保留同步说明。拒绝权限和无搜索结果继续分开。

**验收。** 已有联系人输入无匹配关键词后不再显示空通讯录；清除搜索立即恢复列表，无需重新授权。

### D09 · 中：未连接与首次加载看起来像真实空历史

**证据。** MessagesView 在 messages 为空时立即显示“暂无短信”，同时通过 silently: true 加载；加载失败不会形成对应页面状态。拨号页在 currentAndroidAgent 为空且 pairedAndroidAgents 也为空时不渲染设备卡，跳过首次配对后只能看到拨号盘与禁用按钮。

**建议。** 真正无历史、正在加载、未连接和同步失败分别呈现。已有历史离线时仍可读，并说明是本机副本；无设备时在原卡片区域提供“连接设备”。保留 v2 收件箱缺口提示，但转为简洁说明，不能被正常空态吞掉。

**验收。** 新安装跳过配对后能从拨号页进入连接；无网络打开空短信列表不暗示已经同步完毕；恢复连接后状态随结果更新。已有历史不会因刷新失败而消失。

### D10 · 中：麦克风拒绝后的恢复路径不完整

**证据。** AudioSessionController 拒绝授权仅写入“需要麦克风权限才能进行双向通话”；ActiveCallView 显示最多两行错误文字。原设置没有与通讯录类似的麦克风权限恢复入口。v2 音频错误也仅描述权限未开启。

**建议。** 在相关操作和原设置页显示麦克风权限状态及“前往系统设置”。普通短信通知权限、麦克风与后台来电服务状态分别解释，避免把普通通知授权当作整条来电链路就绪。

**验收。** 拒绝后可直接找到系统设置入口；返回 App 后状态刷新；没有权限时不呈现双向音频已连接。权限弹窗短暂失焦不会被当成用户结束通话。

## 视觉与无障碍调整

| 范围 | 建议 | 验收 |
| --- | --- | --- |
| 导航与层级 | 保留系统标签栏、原蓝色主操作、绿色接听/拨号与红色挂断；版本是设置项和设备副标题，不新增首页 | v1/v2 截图中五标签顺序和核心按钮位置一致 |
| 设备卡 | 名称优先，连接方式与状态次之；异常只有一个主要恢复动作 | 长名称不挤掉状态和设备选择入口；浅色/深色均可读 |
| 通话页 | 保持大号联系人与独立接听/挂断；模块身份次于来电人，错误靠近受影响能力 | 小屏与较大辅助字号下仍能看到接听/挂断，文字不覆盖操作 |
| 短信 | 保留对话气泡和原编辑器；发送中/失败/待确认紧邻对应消息 | 能确定哪条消息失败，草稿和状态不只依靠颜色区分 |
| 时间与技术字段 | 常规列表使用本地可读时间；服务 UUID、设备代次和原始状态进入详情/诊断 | 普通列表无整行 ISO 时间与多个 epoch 并列，仍能追溯来源 |
| 字号与布局 | DialPadLayoutMetrics 的固定高度及首次连接页无滚动布局列入 QA 验证；有裁切时局部调整 | 大字号、小屏、横屏/iPad 下内容可达，不以整体缩小文字代替可读性 |
| 图标按钮 | DialPadView 拨号、MessageThreadView 发送、WatchCallView actionButton 补明确动作标签；不要依赖 SF Symbol 名称 | VoiceOver 读出“拨号”“发送短信”“接听”“拒接”“挂断”，并能获知不可用原因 |

这些是基于结构的调整建议。未观察到截图之前，不认定玻璃材质、颜色对比、圆角、间距或字号已经发生视觉缺陷。

## QA 交接

截图使用虚构联系人、号码和短信；配置页遮蔽凭据。QA 独占模拟器，本审核会话不启动、安装或操作设备。

1. 原 v1 与适配后 v2：相同设备尺寸、浅色/深色、五标签各一张，核对结构一致性。
2. 首次选择、未配置、导入后未选模块、在线、离线、凭据到期：核对状态和下一步，不做真实拨号。
3. 联系人允许/拒绝、空库、无搜索结果；最近记录为空与有数据：核对恢复路径与正确文案。
4. 短信新建、会话回复、发送失败、结果未知、删除失败、离线副本与收件箱缺口：使用可控数据核对草稿、状态与范围。
5. 来电、接听中、通话中、音频不可用、挂断中：核对同一通话身份、按钮和不可用能力，不发起真实通话。
6. 小屏与较大辅助字号、iPad、VoiceOver：检查拨号卡、首次引导和全屏通话的可达性与读序。
7. 系统通知/冷启动、PushKit/CallKit、锁屏及 Watch：由主控授权相应验收，单独记录运行证据，不能以静态截图证明链路通过。

## 已知限制与主控决策点

- 无本轮 QA 截图、模拟器运行或真机证据；本文完成源码层面的全局审核，不宣称视觉和无障碍验收通过。
- R7 推送能力、后台通话归属、跨模块来电订阅及 Watch v2 范围需要主控冻结。当前 R5 仅监控所选模块且 Watch v2 未支持；界面不能自行扩大承诺。
- v2 历史含服务、客户端、模块和设备代次信息。原短信按 sender 分组；复用会话 UI 时必须保留所属服务/模块语义，不能因号码相同合并不同模块的发送目标。具体模型映射由执行方案决定。
- 真实后台来电验收仍需有效 Apple 签名能力、匹配的 APNs 环境、服务端推送配置及目标设备。本轮不变更账户、生产部署或真实通话状态。

建议先由主控确认 D01–D05 的适配行为及 D06–D10 的修复范围，再由 iOS 执行会话实施，QA 按上述场景核对。源码审核文档不代替技术契约。
