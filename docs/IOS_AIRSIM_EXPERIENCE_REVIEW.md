## 使用模式与图解动效

[云端 / USB / 局域网三选一原型](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=3-21&starting-point-node-id=3%3A21)。[图示与动效规范](https://www.figma.com/design/ZQc6KFc7STwqaT0UuY5cIC?node-id=22-510)。

| 模式 | 核心定位 | 图示与能力 |
| --- | --- | --- |
| 云端 | 主号随身，多号待机 | iPhone 主号照常使用；云端生活号、工作号、备用号分别显示待机，电话与短信标明来源 |
| USB | 插线直连，完整使用模块 | iPhone 经数据线连接模块；电话、短信、上网三项并列 |
| 局域网 | 无线连接，能力相同 | iPhone 经局域网连接模块；与 USB 使用相同的电话、短信、上网图标 |

[多号待机与来电来源演示](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=28-632&starting-point-node-id=28%3A632)：点击“演示工作号来电”，工作号卡片高亮、图示状态同步变为来电，其余号码保持待机；点击返回恢复。多号待机不表示多通电话同时进行。
三种选项不叠加开启。点选只更新当前草稿选择，点击“使用…模式”才进入后续引导；设置提供使用模式入口。通话或未知操作期间保留切换约束，不静默改用另一模式。

使用原生可编辑设备图标、矢量连接路径与中文标签表达设备关系。选择状态通过 280 ms Smart Animate 同步改变背景、描边、单选标记与连接指示点，缓入缓出；多号待机与工作号来电采用 350 ms Smart Animate，突出号码来源；进入连接步骤采用淡入。动效只响应操作，不循环闪动。生产实现应在“减少动态效果”开启时静态切换，保留全部状态信息。

当前源码保留 [WiredHTTPTransport](../iOS/AirSIM/WiredHTTPTransport.swift)，但 [AppModel](../iOS/AirSIM/AppModel.swift) 的电话路径使用 moduleLocalReachable=false，moduleLocal 接听分支不可用。USB 保留为一级产品模式，原型展示完整目标流程，当前实现的不可用状态单独保留；支持设备、识别、鉴权、电话与短信接入以及拔线恢复由主控确定，不能从传输代码推断已通过 USB 验收。

USB 与局域网的目标能力均包含上网；普通 Wi-Fi 已连接不等于正在使用模块流量，路由与共享方式需主控确定。云端多号后台待机、USB 完整接入及模块网络共享尚未完成实现或验收。

局域网目标引导面向模块，已有三星配对作为兼容路径保留；各放卡设备接入按实际能力开放。互斥模式对应的路由策略、是否保留旧自动选路行为及兼容处理需主控确认，本轮不修改代码。

## 云端模式引导

[扫码与 PIN 完整原型](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=14-355&starting-point-node-id=14%3A355)从云端介绍、设置添加设备和恢复入口进入。

1. **准备配对码。** 放卡设备或管理页面生成本次二维码与一次性 PIN。分发和自部署版本均提前配置服务器，用户无需填写地址或导入文件。
2. **扫码优先。** 解释相机用途后请求权限，进入取景页；未授权可改用 PIN。识别成功进入设备确认，不直接绑定。
3. **PIN 备用。** 输入配对页面显示的 PIN，不填写手机号，不使用 SIM 卡 PIN。原型采用六位示例，最终长度与有效期由主控确定。
4. **确认设备。** 显示设备名称、标识和号码来源。没有可靠号码时明确显示“号码未提供”，用户核对后确认绑定。
5. **完成连接。** 配对成功后可设置通知，继续检查服务与设备在线状态，再查看我的号码、主动试用电话短信或添加其他号码。

恢复状态包含相机未授权、PIN 错误、配对码过期/已使用/服务不匹配、设备已有归属或未获允许、配对提交后网络中断、绑定后设备离线。结果未知时查询本次结果；设备离线保留绑定，不要求重新扫码。不会自动解除已有归属。

扫码与 PIN 共用同一配对授权与设备确认流程。旧文件和手填地址画板已从可点击原型移除，相关设置与恢复入口同步调整。动效采用 280 ms 状态过渡，系统权限衔接采用淡入；减少动态效果时静态切换。系统授权、扫码、输入与异步结果为离散演示。

产品代码与服务未变更。配对凭据的生成方式、有效期、PIN 查找规则、归属校验和绑定接口由主控确定；设计不把尚未实现的二维码或 PIN 流程描述为已上线。

## USB 与局域网完整引导

- [USB 连接与使用](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=21-493&starting-point-node-id=21%3A493)：模块供电与 SIM 准备 → 数据线连接 → 发现并核对模块 → 设备授权 → 分别检查电话、短信、上网 → 三项使用教学。
- [局域网连接与使用](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=21-528&starting-point-node-id=21%3A528)：模块供电 → iPhone 加入模块 Wi-Fi 或共同局域网 → 本地网络权限 → 发现并核对模块 → 设备授权 → 三项能力检查与教学。

新增 35 个流程与状态画板。连接图在准备和断开状态弱化，识别后恢复完整显示；以 300 ms Smart Animate 过渡，状态同时由文字表达。完成页的电话、短信、上网图标及下方按钮均可进入对应教学；减少动态效果时直接静态切换。

| 教学 | 内容 |
| --- | --- |
| 电话 | 认清模块号码，选择联系人或输入号码，按需允许麦克风；演示拨出、接听、通话和挂断，说明保持线缆或局域网连接 |
| 短信 | 明确发送来源、收件人和草稿，演示发送成功与接收入口；结果未知时查询原操作，避免重复发送 |
| 上网 | 模块启用移动数据和网络共享，确认 iPhone 上网路径，再用网页验证；流量计入模块 SIM 卡套餐 |

USB 使用数据线而非仅充电线，并按设备要求供电、使用兼容转接器。局域网优先展示模块提供的 Wi-Fi，亦提供共同局域网分支。共同局域网可发现设备不代表已经使用模块流量，其上网路径由设备管理者预先配置。

异常分支覆盖线缆/供电/兼容性、Wi-Fi 不可见、本地网络权限拒绝、设备配对码不可用、SIM 未就绪、网络共享未就绪及断线恢复。电话、短信和上网分开呈现状态；断线不清记录，不静默切换模式，不自动重拨或重发。

设备授权以一次性配对码表达目标交互；码格式、USB 接口、模块热点、共享方式和路由检测由主控确定。系统 Wi-Fi 设置、权限和运营商结果均为交互演示，尚未完成 USB 或网络共享的实机验收。

首页与设置同时展示当前模式、号码昵称、设备及连接状态。没有可靠电话号码时显示“号码未提供”。云端显示各号码的待机状态；USB 与局域网分别显示电话、短信、上网能力。连接完成入口进入对应首页，五标签保留对应模式的导航上下文。

从设置选择目标模式后，先确认原号码、目标号码及上网/接听影响。确认后准备目标连接，目标就绪才更新当前模式；取消或失败保留原模式与号码，不转移历史记录。切换采用 280 ms 状态过渡，减少动态效果时静态切换。

通话进行中禁止切换，提示可返回通话或主动挂断后选择模式，不自动挂断或排队执行切换。普通断线保留模式与号码，阻止新电话和短信，按云端、USB、局域网分别给出恢复说明。

通话断线显示“通话状态待确认”，不能据此认定运营商通话结束。恢复后核对同一通话：仍在进行则返回通话，已结束才允许重拨或切换；持续离线时提示到放卡设备确认，保留当前模式。原型的成功、失败、断线和挂断按钮是演示结果，不调用实际设备。

## 云端多号码管理与使用

[完整多号码原型](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=53-1525&starting-point-node-id=53%3A1525)已接入云端首页和设置。生活号、工作号、备用号分别显示设备与状态；没有可靠号码时写明“号码未提供”。

- **管理：** 查看单号码详情、修改昵称、添加号码、确认从本机移除。昵称不改变 SIM 或设备身份；移除停止本机使用该号码，保留历史来源，不注销 SIM 或解除服务端归属。
- **拨号：** 明确选择本次使用的在线号码，确认对方与本方来源后拨打；取消选号回到原拨号确认。选择本次号码不影响其他号码待机。
- **短信：** 新短信选择本次发送号码，换号保留收件人与草稿。发送结果未知时保留原号码并查询原操作，阻止换号重复发送。
- **接收：** 来电显著显示打给哪个本方号码；短信列表和会话头标注本方号码与设备。同一联系人按不同本方号码拆分会话，回复默认使用原接收号码；改用其他号码进入新建短信。
- **并发与异常：** 离线号码不可选，通话中不能换号。另一号码来电明确区分当前通话与新来电，可保留当前通话或结束后再接听，不自动转移或并行建立两通电话。

原型以生活号、工作号演示双向选号和接收归属，备用号演示离线限制。号码列表、昵称和本机移除采用离散示例状态；设备身份映射、真实号码来源、持久化、服务端归属和多号后台接收由主控确定。本轮未实现相关协议或运行时行为。

## 最近通话与联系人

- [最近通话与回拨选号](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=48-1471&starting-point-node-id=48%3A1471)

三种模式的最近通话分别标记当时的本方号码、设备和模式，详情保留呼入/呼出/未接、时间、时长与对方身份。历史归属不随当前模式或号码选择变化。点击记录只打开详情；回拨和短信先带入原号码供用户确认，支持显式换号。原号码离线时无法直接提交，可主动选择其他在线号码，确认对方将看到新的号码。

联系人详情分开呈现对方手机与工作电话，再进入本方号码确认。云端可选择生活号或工作号，换号保留对方和短信草稿，取消返回原操作；工作电话分支在确认和通话中持续标注。USB/局域网确认当前随身号，只有一个可用号码时解释需切换模式后重新确认，不伪造可选 SIM。

各入口复用既有拨号、短信、发送结果与通话演示。来源不同的确认页保留对应记录或联系人返回路径，不从记录页直接发起真实呼叫。新增动效采用 280 ms 状态过渡，减少动态效果时静态切换。

## 短信列表、筛选与会话状态

[短信完整交互](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=64-2290&starting-point-node-id=64%3A2290)已连接云端、USB、局域网首页，以及联系人和最近通话的发短信入口。

列表支持全部号码、生活号、工作号和备用号筛选。筛选不改变发送号码；每条会话保留本方号码，离线号码仍可查看本机记录，无记录时明确显示空态。USB 和局域网显示当前随身号范围。

| 状态 | 会话表现与下一步 |
| --- | --- |
| 收到 | 左侧对齐，向下标记与收到时间；回复默认原接收号码 |
| 发送中 | 右侧蓝色状态，显示发送中；等待结果，不重复提交 |
| 已发送 | 右侧显示已发送；不等同于已读或对方确认收到 |
| 明确失败 | 警示底色与失败文字，保留正文；确认号码、收件人和正文后重发 |
| 结果待确认 | 说明连接中断导致结果未知；查询原操作，无直接重发入口 |

回复与重发均先确认本方号码。改用另一在线号码时，保留收件人及正文，以新短信发送，原会话和失败记录保留归属。USB/局域网只有当前一个号码时，引导切换模式后重新确认，不伪造第二个 SIM。

新建、回复和重发各自进入发送中、成功、明确失败或结果未知的示例分支，号码与正文贯穿同一次操作。原型不访问真实短信或设备。

## 通知与后台来电

[通知权限、锁屏与后台来电原型](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=71-2887&starting-point-node-id=71%3A2887)接入三种模式设置、电话权限、接听帮助及云端配对提醒步骤。

锁屏来电分别标明生活号/工作号和设备；接听进入对应通话的连接中状态，音频接通后才显示通话中。拒接或来电已结束进入该号码的对应记录，不自动回拨。来电通知过期不能重新接听，设备离线不能显示已接通；恢复后先核对是否仍在响铃。

短信锁屏卡片显示本方号码昵称，支持内容预览与仅显示新短信的示意。点击后按通知中的本方设备、号码和会话定位，必要时先解锁与同步，不采用当前筛选或上次发送号码。设备离线时显示本机只读会话，恢复后再允许回复；号码已移除时提示管理或重新配对，不跳转到其他号码。

短信通知权限包括未请求、允许、拒绝和从系统设置返回后重新读取状态。普通通知的锁屏、声音与专注设置单独说明；打开设置不等于授权成功。后台接听按模式和版本能力展示，当前 v2 仍需前台等待，已有通话的后台保持与空闲后台唤醒分别说明。

依据 Apple 的[通知授权说明](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications)与[PushKit 来电处理说明](https://developer.apple.com/documentation/pushkit/responding-to-voip-notifications-from-pushkit)，普通通知授权与系统来电路径分别设计。系统界面为可编辑交互示意，最终外观与可用控件由 iOS 决定。本轮没有实施推送、后台唤醒或生产配置。

当前产品保留 local、v1、v2 和原五标签。v2 通过管理员签发的临时连接文件接入，首次显式选择设备；这是当前源码状态，与本轮目标配对设计分开。R7 文档记录 15 项 UI 自动化通过、132 项单测中 131 通过和 1 项硬件条件跳过；真机呼出、前台发现来电后的系统接听、已有通话后台保持和 App 挂断已通过限定范围验收。本轮引用这些记录，不重复认定为本轮测试。

当前 ECS 生产保持 R4.1。v2 空闲后台与冷启动来电唤醒、Watch v2、交互登录和自动二维码配对未提供。

## 体验问题与优先级

### P1 · 连接入口要求先懂版本

源码 AirSIMRuntimeChoice / AirSIMFirstConnectionView。首次进入要先选择 local/v1/v2，再理解不同连接材料。建议先按云端、USB、局域网三种产品模式组织任务，技术选项仍可找回。

### P1 · 连接流程缺少完整引导

V2ConnectionSections 直接呈现导入、模块选择和完成按钮。需要补齐获取文件、无设备、导入失败、过期、退出继续和第一通电话，不以结束引导代替连接就绪。

### P1 · 号码归属不够直观

当前设备显示为“模块·短标识”；普通用户难以知道电话与短信使用哪张卡。建议改为“放卡设备”，所有关键操作显示当前设备；无号码来源时明确显示未知。

### P1 · 接听限制出现在设置说明中

已有说明准确，但首次连接完成时也需看到。建议在连接完成和接听教学中明确前台等待条件，不让“已连接”暗示可以锁屏待机收来电。

### P2 · 设置按实现方式分组

连接版本、云端 v2、系统通话与诊断混合。建议按设备、电话、外观、帮助、高级分组；旧连接功能和技术支持入口仍保留。

### P2 · 首次教学与设置找回路径不足

当前无统一帮助中心与重看新手教学入口。建议从设置和异常状态直达相关步骤；权限在功能第一次使用时解释，不集中索取。

## 设计决策

1. **保留五标签。** 拨号、最近、短信、联系人、设置继续共用原界面；连接版本不产生第二套 App 导航。
2. **使用模式三选一。** 云端、USB、局域网为同级互斥模式。初次不默认选中，点选更新图示，确认后进入对应引导。云端以预配置服务器后的扫码与 PIN 配对为入口，识别后先确认设备再绑定。产品模式不等于 local/v1/v2 技术运行时，映射与切换实现由主控冻结。
3. **区分连接与通话可用。** 配对码识别、设备绑定、设备在线、运营商任务成功是不同状态。教学结束不等于连接成功。
4. **显示真实号码归属。** 拨号、撰写和通话页显示当前放卡设备。当前无法可靠获得号码时写“号码未提供”，不把设备短标识冒充号码。
5. **权限按使用时机请求。** 附近配对请求本地网络，首次通话请求麦克风，使用联系人时请求通讯录。拒绝权限不阻止其他可用任务。
6. **保留恢复上下文。** 离线不清历史；明确发送失败保留正文；结果未确认仅查询原操作，不建议直接重发或重拨。
7. **帮助常驻可找回。** 设置提供帮助、新手教学重看、接听说明、连接恢复和短信结果核对。
8. **危险操作说明对象。** v2 清理仅影响当前设备本机短信副本；旧连接删除还会影响设备尚未交付的短信，两种确认分别呈现。
9. **使用语义化视觉。** SF Pro、浅深语义色、可增长文字布局、至少 44 点触达。状态不只用颜色表达。

## 给 iOS 执行端的变更建议

| 工作包 | 明确变更 | 验收结果 |
| --- | --- | --- |
| 首次连接 | 云端采用扫码与 PIN，补齐权限、设备确认、绑定结果与在线检查；局域网保留三星配对器 | 取消可回退；识别不等于绑定；未知结果先查询；离线保留绑定；旧用户不强制重新教学 |
| 五标签状态 | 每个关键操作显示当前放卡设备；分别展示未配置、加载、离线、空记录和同步缺口 | 有历史时不被错误空态覆盖；切换设备不混淆记录和操作对象 |
| 拨号与通话 | 保留原拨号和通话控制，增加号码归属与按需麦克风说明 | 输入数字不触发呼叫；单次点击只提交一次；音频中断仍可挂断；通话键盘只发送当前通话的按键 |
| 最近与联系人 | 详情明确回拨/发短信；多号码选择；大字姓名与号码换行 | 联系人首次及再次发短信进入正确收件人；完整号码可读 |
| 短信 | 保留原撰写器；明确失败与未知结果分开；两类清理确认分别写明后果 | 接受命令不提前显示已发送；成功再清正文；未知操作只查询；拒绝保留正文 |
| 设置 | 按设备与连接、电话与权限、外观与语言、帮助、高级分组，落实逐项对照 | 普通设置不要求理解协议、服务端或凭据；原功能能通过支持入口找回 |
| 教学与帮助 | 增加重看、继续连接、接听限制和任务恢复说明 | 教学可返回、可跳过、可重看；限制在任务时机出现 |
| 无障碍 | 系统字号、纵向滚动、语义颜色、VoiceOver 标签与结果播报 | 小屏和最大辅助字号仍可读设备、号码、原因和主操作，不靠缩字适配 |

文案和分组可在现有能力上实施；涉及新状态存储、资料来源或运行时行为的部分需先由主控确认。

| 问题 | 体验建议与取舍 |

## 校验与已知限制

Figma 原型页面包含 389 个屏幕画板；检查时有 1259 个画板跳转动作，目标节点均存在，屏幕直接子层未越过画板底部。模式能力图由可编辑原生图标、文字和组件组成。已截图检查三种模式选中状态、多号来电来源，以及扫码、PIN 输入、设备确认、USB/局域网连接、三项能力完成页、上网教学、首页设置、模式切换确认、通话断线、多号码管理、发短信选号、来电与短信来源、最近通话、联系人详情、回拨与联系人发信确认、短信筛选、会话状态、发送中、锁屏来电短信及通知权限页面。

原型使用虚构演示资料。文件选择、系统授权、文字输入、键盘、异步结果及部分开关用离散状态演示，不能代替真实系统交互或端到端测试。大字画板是重排示例，不等于全量 Dynamic Type 验收。

产品能力限制集中展示：v2 等待来电需要 App 前台，已有通话可切后台；Watch v2、交互登录、自动扫码配对和后台唤醒不作为可用流程。当前实现依赖管理员签发文件；目标原型使用扫码或一次性 PIN，实际实施需要设备端与服务端配套。本轮评审无需用户提供密钥、签名或真实号码。
