## 使用模式与图解动效

[云端 / USB / 局域网三选一原型](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=3-21&starting-point-node-id=3%3A21)。[图示与动效规范](https://www.figma.com/design/ZQc6KFc7STwqaT0UuY5cIC?node-id=22-510)。

| 模式 | 核心定位 | 图示与能力 |
| --- | --- | --- |
| 云端 | 主号随身，多号待机 | iPhone 主号照常使用；云端生活号、工作号、备用号分别显示待机，电话与短信标明来源 |
| USB | 插线直连，完整使用模块 | iPhone 经数据线连接模块；电话、短信、上网三项并列 |
| 局域网 | 无线连接，能力相同 | iPhone 经局域网连接模块；与 USB 使用相同的电话、短信、上网图标 |

[多号待机与来电来源演示](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=28-632&starting-point-node-id=28%3A632)：点击“演示工作号来电”，工作号卡片高亮、图示状态同步变为来电，其余号码保持待机；点击返回恢复。多号待机不表示多通电话同时进行。
三种选项不叠加开启。点选只更新当前草稿选择，点击“使用…模式”才进入后续引导；设置提供使用模式入口。通话或未知操作期间保留切换约束，不静默改用另一模式。

使用原生可编辑设备图标、矢量连接路径与中文标签表达设备关系。选择状态通过 280 ms Smart Animate 同步改变背景、描边、单选标记与连接指示点，缓入缓出；多号待机与工作号来电采用 350 ms Smart Animate，突出号码来源；进入连接步骤采用淡入。动效只响应操作，不循环闪动。生产实现应在“减少动态效果”开启时静态切换，保留全部状态信息。

当前源码保留 [WiredHTTPTransport](../iOS/AirSIM/WiredHTTPTransport.swift)，但 [AppModel](../iOS/AirSIM/AppModel.swift) 的电话路径使用 moduleLocalReachable=false，moduleLocal 接听分支不可用。USB 保留为一级产品模式，当前原型明确显示暂不能使用；支持设备、识别、鉴权、电话与短信接入以及拔线恢复由主控确定，不能从传输代码推断已通过 USB 验收。

USB 与局域网的目标能力均包含上网；普通 Wi-Fi 已连接不等于正在使用模块流量，路由与共享方式需主控确定。云端多号后台待机、USB 完整接入及模块网络共享尚未完成实现或验收。

局域网当前兼容引导落到已支持的三星配对；其他放卡设备的局域网接入按实际能力开放。互斥模式对应的路由策略、是否保留旧自动选路行为及兼容处理需主控确认，本轮不修改代码。

## 云端模式引导

[云端模式完整原型](https://www.figma.com/proto/ZQc6KFc7STwqaT0UuY5cIC?node-id=14-332&starting-point-node-id=14%3A332)从首次场景选择和帮助页均可进入，包含云端连接引导及两个新增的多号待机、工作号来电演示画板。

- **认识云端模式：** iPhone 与放卡设备各自联网，不必在同一 Wi-Fi。SIM 卡仍在放卡设备中；设备需保持开机联网，两端会消耗流量。
- **连接文件路径：** 获取材料 → 导入已有文件 → 显式选择设备 → 云端连接完成 → 查看接听限制 → 在不同网络下主动试用。当前 v2 仍需前台等待来电。
- **三星远程地址路径：** 确认已有配对或完成附近配对 → 填写远程服务地址 → 通知说明与拒绝分支 → 运行现有远程连接检查 → 查看实际结果 → 分别验证拨号、接听和短信。
- **恢复路径：** 无连接材料、配对失败、通知未开启、服务不可达、设备离线分别给出下一步。系统通知权限与后台来电能力分别说明；不把自检通过写成运营商任务已通过。

面向用户的目标流程使用预配置服务器：分发版本由发布者配置，自部署版本由部署者提前配置在 iOS App 中。普通用户无需填写服务器地址。现有连接文件与三星远程地址画板保留为当前实现的兼容说明；后续云端配对流程由主控确认。现有本地配对完成页提供“继续设置云端模式”，避免远程设置只能从高级入口找回。

画板中的系统输入、授权和检查结果为交互演示。新增组合流程与原运行时切换、配对身份、注册顺序的衔接由主控确认，产品代码和服务配置未改变。

## 体验问题与优先级

### P1 · 连接入口要求先懂版本

源码 AirSIMRuntimeChoice / AirSIMFirstConnectionView。首次进入要先选择 local/v1/v2，再理解不同连接材料。建议先按云端、USB、局域网三种产品模式组织任务，技术选项仍可找回。

### P1 · 连接流程缺少完整引导

V2ConnectionSections 直接呈现导入、模块选择和完成按钮。需要补齐获取文件、无设备、导入失败、过期、退出继续和第一通电话，不以结束引导代替连接就绪。

### P1 · 号码归属不够直观

当前设备显示为“模块·短标识”；普通用户难以知道电话与短信使用哪张卡。建议改为“放卡设备”，所有关键操作显示当前设备；无号码来源时明确显示未知。

### P1 · 接听限制出现在设置说明中

已有说明准确，但首次连接完成时也需看到。建议在连接完成和接听教学中明确前台等待条件，不让“已连接”暗示可以锁屏待机收来电。

### P2 · 设置按实现方式分组

连接版本、云端 v2、系统通话与诊断混合。建议按设备、电话、外观、帮助、高级分组；旧连接功能和技术支持入口仍保留。

### P2 · 首次教学与设置找回路径不足

当前无统一帮助中心与重看新手教学入口。建议从设置和异常状态直达相关步骤；权限在功能第一次使用时解释，不集中索取。

## 设计决策

1. **保留五标签。** 拨号、最近、短信、联系人、设置继续共用原界面；连接版本不产生第二套 App 导航。
2. **使用模式三选一。** 云端、USB、局域网为同级互斥模式。初次不默认选中，点选更新图示，确认后进入对应引导。云端以预配置服务器后的号码绑定为目标；连接文件和远程地址仅保留兼容入口。产品模式不等于 local/v1/v2 技术运行时，映射与切换实现由主控冻结。
3. **区分连接与通话可用。** 文件导入、设备选定、设备在线、运营商任务成功是不同状态。教学结束不等于连接成功。
4. **显示真实号码归属。** 拨号、撰写和通话页显示当前放卡设备。当前无法可靠获得号码时写“号码未提供”，不把设备短标识冒充号码。
5. **权限按使用时机请求。** 附近配对请求本地网络，首次通话请求麦克风，使用联系人时请求通讯录。拒绝权限不阻止其他可用任务。
6. **保留恢复上下文。** 离线不清历史；明确发送失败保留正文；结果未确认仅查询原操作，不建议直接重发或重拨。
7. **帮助常驻可找回。** 设置提供帮助、新手教学重看、接听说明、连接恢复和短信结果核对。
8. **危险操作说明对象。** v2 清理仅影响当前设备本机短信副本；旧连接删除还会影响设备尚未交付的短信，两种确认分别呈现。
9. **使用语义化视觉。** SF Pro、浅深语义色、可增长文字布局、至少 44 点触达。状态不只用颜色表达。

| 拨号与通话 | 保留原拨号和通话控制，增加号码归属与按需麦克风说明 | 输入数字不触发呼叫；单次点击只提交一次；音频中断仍可挂断；通话键盘只发送当前通话的按键 |
| 最近与联系人 | 详情明确回拨/发短信；多号码选择；大字姓名与号码换行 | 联系人首次及再次发短信进入正确收件人；完整号码可读 |
| 短信 | 保留原撰写器；明确失败与未知结果分开；两类清理确认分别写明后果 | 接受命令不提前显示已发送；成功再清正文；未知操作只查询；拒绝保留正文 |
| 设置 | 按设备与连接、电话与权限、外观与语言、帮助、高级分组，落实逐项对照 | 普通设置不要求理解协议、服务端或凭据；原功能能通过支持入口找回 |
| 教学与帮助 | 增加重看、继续连接、接听限制和任务恢复说明 | 教学可返回、可跳过、可重看；限制在任务时机出现 |
| 无障碍 | 系统字号、纵向滚动、语义颜色、VoiceOver 标签与结果播报 | 小屏和最大辅助字号仍可读设备、号码、原因和主操作，不靠缩字适配 |

文案和分组可在现有能力上实施；涉及新状态存储、资料来源或运行时行为的部分需先由主控确认。

原型使用虚构演示资料。文件选择、系统授权、文字输入、键盘、异步结果及部分开关用离散状态演示，不能代替真实系统交互或端到端测试。大字画板是重排示例，不等于全量 Dynamic Type 验收。

产品能力限制集中展示：v2 等待来电需要 App 前台，已有通话可切后台；Watch v2、交互登录、自动扫码配对和后台唤醒不作为可用流程。连接需要实际放卡设备及管理员提供的有效文件。本轮评审无需用户提供密钥、签名或真实号码。
