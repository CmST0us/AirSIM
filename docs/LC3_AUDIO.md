# v2 LC3 音频

v2 云端和 USB 本地媒体使用固定 LC3 配置。模块原生 `airsim-audiod` 与 iOS App 负责编解码，Go Agent 和 ECS 仅验证、排队和转发压缩帧。外部格式为 16 kHz 单声道 S16LE。EG25 的 VoLTE 前端与 AFE 代理端口直接以 16 kHz 采集和播放；RM500 采集为 8 kHz，由 helper 插值到 16 kHz，播放按声卡实际速率直出或经 [1 2 1]/4 低通后降至 8 kHz。

## 格式与带宽

| 项目 | 配置 |
| --- | --- |
| 编解码库 | Google liblc3 v1.1.3，标准 LC3，关闭 LC3 Plus／HR |
| 采样率／声道 | 16 kHz／单声道 |
| 编码帧 | 10 ms，160 个样本，40 bytes |
| 每包音频 | 两帧，共 20 ms／320 个样本／80 bytes |
| ASMP | 版本 2，40-byte 头，总长 120 bytes |
| 序号 | 每个 20 ms 包递增 |
| 丢帧补偿 | 接收端对每个缺包执行两次 LC3 PLC |

每方向音频载荷为 32 kbps，16 kHz PCM 为 256 kbps，减少 87.5%；含 ASMP 头为 48 kbps，不包含 WebSocket、TLS、TCP/IP 开销。由 8 kHz 升到 16 kHz 时码率、ASMP 包长和 20 ms 包率均不变，同一码率覆盖 7 kHz 宽带。

库报告的算法延迟为 40 个样本，即 2.5 ms；不包含成包、起播缓冲、网络或硬件队列延迟。模块和 App 在播放出队时解码，空队列或 erasure 包触发 PLC，不把全零字节当成合法编码静音。真实输入超时和媒体 generation 的生命周期继续生效。

接收端按网络路径分别设置抖动缓冲。App 接收模块音频、Agent 接收 App 音频时，100 ms 起播、最多 12 包、超过 240 ms 丢弃；模块采集发往云端的队列保持 40 ms 起播、五包、100 ms 过期。App 收发队列与 Agent 的两个转发方向在计时晚到时逐包追播（Agent 相邻输出至少间隔 5 ms），不再跳过时隙，滞后超过队列过期时间才重新对齐；App 发送队列 40 ms 起播、最多 12 包，可容纳单次约 100 ms 的麦克风回调，采集缓冲为 15 帧。原生 helper 播放队列为四包，队列为空时最多等待 15 ms 新包再补偿，Agent 按同一上限校验 `queue_peak`。App 播放节点累积两包后开始，最多排队六包，播空后重新累积。App 采集经 AVAudioConverter 降采样至 16 kHz。

云端媒体建连与双方配对的等待上限为 20 秒，并受媒体票据的绝对有效期限制。EG25 公网 WebSocket 升级实测约 6.25 秒，超过原五秒预算；模块、服务端与 App 使用配套期限，避免对端提前关闭。通话中的两秒缺帧超时、发送期限及播放队列规则不变。

队列丢弃保留源序号缺口。解码前抵扣已经播放的 PLC，再为最多五个未补偿包推进解码状态并丢弃其输出；更长缺口直接重置历史。这样既保持实时丢旧包，也避免将不相邻音频的滤波和重叠历史直接拼接。桥接序号映射与解码器的会话状态分别重置。

完整字段、鉴权和帧标志见 [R4](../protocol/v2/R4.md) 与 [USB 本地协议](../protocol/v2/USB_LOCAL.md)。`sample_format=s16le` 描述解码后的 PCM；编码由 `codec=lc3`、`codec_frame_us=10000`、`codec_frame_bytes=40` 指定。

## 构建与更新

共享封装位于 `shared/lc3/`，固定版本源码及来源记录位于 `third_party/liblc3/`。iOS 主 target 编译同一份 C 代码；RM500 与 EG25 helper 分别静态构建 ARM64 与 ARMv7。Go Agent 保持 `CGO_ENABLED=0`。第三方许可随 App 和网页安装包分发。

LC3 版 App、ECS control／media、Agent 和 helper 必须配套更新，不能在通话中切换。旧 Agent 未声明 LC3 能力时仍保持控制连接，媒体请求返回不可用；旧 PCM 媒体不能混入 ASMP v2。Agent 验证 helper 的 codec 信息，避免误用旧 helper。

更新前确认无活动通话并保留回滚：服务器保存原 control／media 镜像与部署配置，模块保留配套的 Agent 和 helper。模块切换 `current` 与 `audio-current` 后由既有 init 监督恢复；失败时两个链接一并恢复，保留身份、配对、平台驱动和状态。网页安装资源包含两个平台的新 Agent、helper 与 `LC3-LICENSE.txt`。

## 验收边界

2026-10-31 iPad 真机接听、挂断、CallKit 音频激活与媒体 HTTP 创建通过。直连通话中，App 在接听后约一秒取得通话所有权，媒体 HTTP 创建约 61 ms 完成；模块随后约十五秒在连接阶段失败，双方尚未配对，未进入音频传输。独立回执轮询已在真机生效，但媒体连接和实际双向声音仍未通过验收。

模块已部署固定连接错误分类，区分 DNS、TCP、TLS、HTTP 及取消；TCP 与 TLS 超时分别记录，保留原超时和错误链。无通话时，同 Go 1.24.13、证书根和域名下，Agent 自定义传输约 998 ms、标准 Transport 约 509 ms 完成 TLS 并取得 HTTP 200，尚未复现通话时的连接超时。内核现有日志没有 OOM 或分配失败记录，但缺少相关内存压力计数，不能据此排除内存因素。

真实 TLS＋Unix 媒体桥双向 50fps 持续九秒测试，以及 Relay 双向 50fps 持续八秒、各 400 包逐字节验证均通过，未复现自发断流。三端诊断仅记录固定错误类别、数值统计与时间间隔，不记录通话身份、号码、票据或音频内容。

同一 EG25 蜂窝连接、ECS 媒体服务、ASMP erasure 包和超时规则下，公网路径对照将断流定位到 Cloudflare 代理／Tunnel 路径。直连测试保留原域名的 TLS 证书校验与 SNI，仅在临时探针中指定源站地址；生产客户端不固定 IP。
