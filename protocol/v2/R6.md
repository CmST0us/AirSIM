## M1 实施裁决

1. 仅扩展已有 DEBUG 诊断。真机可查看固定错误码/阶段、资格失败与快照年龄、收发帧/丢弃/补零/写超时、实际采样率/声道、VoiceProcessing、引擎运行状态。把通用信息从 simulator 条件移出；提示语/回声开关、本机合成音测试和主动断媒体按钮继续限制 DEBUG simulator，不在真机提供注入入口。
2. 音频路由只记录系统 portType 固定分类（内置麦克风、听筒、扬声器、有线、蓝牙、其他、无），不记录设备名称/UID。启动、真实 route-change、扬声器切换后更新；实际路由与请求的 speaker 布尔值分别显示。不要为记录路由重启引擎或改变其失败策略。

4. 主 App/扩展 bundle 不改。此轮专用 Debug 构建使用现有 Apple Development identity、Team `2VQ94C2355`、自动签名，允许 Xcode 为指定已连接设备完成必要的注册和 provisioning。命令行 `CODE_SIGN_ENTITLEMENTS=` 仅对此次前台 v2 构建移除 push/default calling/default messaging 等能力要求；不修改仓库 entitlement、team 或发布配置，不把本轮当成这些能力的验证。若账号认证/描述文件仍不足，报告具体错误，不自行换团队、创建证书或替换其他设备配置。

实际首轮失败：占位 `com.example.airsim` 无法注册，空命令行 entitlement 未消除 Xcode 对源 entitlement 能力的检查。用户已在平台注册手机，刷新后的 wildcard development profile 已包含目标设备及有效证书。主控采用 `/tmp/airsim-r6-device-project` 独立源码副本，主 App 标识 `com.eric3u.airsim.r6`，扩展/Watch 使用其对应后缀；副本的 entitlement 文件为空。Xcode 拒绝把 Xcode-managed profile 当作手动 profile，因此副本使用既有团队和证书自动选择匹配 profile 签名。仓库占位标识、能力和团队设置不变。副本主 App 显示名 `AirSIM R6`，仅验收副本开启 Documents 文件共享及原地打开，用正常文件选择器导入短期配置。业务存储仍在 Application Support/Keychain，不把短信或凭据另存为共享文件。

用户明确要求 UI 自动化操控真机。Device Hub 提示当前屏幕共享要求 iOS 27，而目标为 iOS 26.5.2，因此使用独立的 XCTest UI runner，通过正常控件读取/点击/输入驱动已安装 App。驱动只存在本地验收工程，不加入生产 App；不注入业务 API、音频或自动拨号逻辑，不绕过权限。主控每次按实际 UI 状态下发有限动作，来电和稳定性测试仍绑定本轮授权号码及通话。参考 [Apple XCUIAutomation](https://developer.apple.com/documentation/XCUIAutomation)、[Documents 文件共享](https://developer.apple.com/documentation/BundleResources/Information-Property-List/UIFileSharingEnabled)。

用户已确认两台手机均在身边。正常 App 文件导入、Keychain、discovery、模块显式选择、实验音频开关、权限弹窗均需走 UI，不增加自动拨号/绕过权限/写入私有偏好的后门。签名安装完成后再签发独立短期 client，凭据不进 Git、日志或 URL，结束撤销并删除本轮创建的临时文件。

真实对话要区分手机间直接空气串音与通话：适当拉开距离，发送端靠近麦克风低声讲话、接收端单独听对端。分别确认 App→运营商手机、运营商手机→App，静音时只有对应方向消失，取消静音恢复；实际扬声器 portType 必须确认。观察无主动切断的持续通话，记录两端可闻断续而非用帧计数声称声音质量合格。仅对本轮同 call_id、boot/backend/connection 绑定设置有界超时挂断守卫，不自动重拨。

## M3 性能修复第一步裁决

第二通真实双向可闻但断续，且媒体在电话挂断前停止，稳定性未通过。先移除已确定的重复计算，再用聚合计时定位剩余问题，不凭用户“像信号不好”的描述判断根因。

1. `V2Snapshot` 仅在严格解码时解析一次不可变 `observed_at`，保存派生 `Date`；同一快照的绑定、匹配、新鲜度和诊断复用该结果。每次仍以当前 `now` 检查原有 `[-3,8]` 秒窗口及 online、身份、epoch、call 条件，保留原始字符串和全部严格解析。不得将派生字段加入 wire schema，不做全局缓存。
2. DEBUG 仅增加有界聚合计时：配对时长、tick 间隔达到 20ms 的次数与最大值、资格检查次数/累计与最大耗时、成功写入最大耗时，以及上下行队列/跳槽、采集输出丢弃和播放丢弃分项。用单调时钟，仍每秒发布，停止冻结、新会话清零，不记录逐帧内容。
3. 本步不改 timer、队列节拍算法、容量、超时、网络 profile、ECS 或 Agent。测试严格无效时间拒绝、同一快照随当前时间变陈旧、边界、offline/epoch/call 隔离及统计生命周期。执行会话落地和测试，主控审查提交与真机安装复测。

## M3b 轮询隔离裁决

App 末次停止原因是快照 8.005 秒过期，最近有效音频仅在 80ms 前。既有 snapshot/messages/directory 串行链中的每次 HTTP 可等待 5 秒，短信或目录慢查询会延迟下一次状态查询；本次具体哪条请求慢尚未测得。

将 snapshot、messages、directory 改为三条独立、每类单飞的只读循环，各自保留错误退避，成功后分别等待 1/1/5 秒。Snapshot 成功立即消费并更新媒体资格，不等待短信、目录或收据；原 pending recover 保留在 messages 辅助循环，仍按原 busy、generation 与只读核对规则。各循环错误单独记录，其他循环成功不掩盖尚未恢复的错误。停止、后台、切模块、配置与 401 均失效 generation、取消全部循环；可等待的生命周期路径等待全部退出，晚响应不得应用旧状态。HTTP 5 秒、新鲜度 8 秒、原媒体规则不变。

受控测试分别阻塞短信与目录，确认快照至少继续两次并保持新鲜；验证后台、切模块及 401 后旧响应不能更新状态。本步不更改历史存储、服务器或硬件。
