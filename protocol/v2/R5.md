# R5：iOS App 接入 ECS v2（主控契约）

2026-10-24。主控负责技术决策，iOS 执行会话仅按本文件实现。沿用 R4 的 `airsim-v2-r4.1` 网络契约，不把 App 阶段编号改成服务端 profile。用户要求保留 v1/v2 选择、App 通话/SMS/双向音频闭环，并进一步指定先使用模拟器。原 R4 实机结果不能充当 App 结果。

## 范围与里程碑

- M1：独立 v2 配置/Keychain、严格数据模型、HTTPS 客户端、命令状态机、ASMP 编解码与有界媒体队列；隔离协议测试、编译。
- M2：版本选择与运行生命周期隔离、明确模块选择、前台通话/SMS UI、旧版回归。
- M3：独立 v2 音频引擎与媒体 WSS、静音/扬声器、故障回收；本地协议/音频边界测试。
- M4：模拟器 App → 公网 ECS → RM500 的通话、SMS、75秒媒体内容与故障恢复；用户确认听感，单独记录音频注入与真实麦克风路径。主控独占 ECS、ADB、凭据和真实电话。

本轮是前台实验客户端。ECS discovery 的 `apns:false`、`interactive_login:false` 必须如实显示；不使用后台静音保活替代 APNs，不宣称锁屏/杀进程来电、正式登录、Watch v2 或实体 iPhone 音频已通过。Agent 的 voice_ready 发布门槛不改。M2/M3 的详细生命周期/音频裁决由主控补充后启动，M1 不自行实现这些部分。

## M1 已冻结：配置及身份

1. 新增独立 v2 类型，放 `iOS/AirSIM/CloudV2/`；不得把 v2 响应硬塞进旧 `AgentHealth/CallRecord/CloudCallSession` 等协议对象。不修改 service/、module/、旧 Worker。工程文件加入新文件仅限主 App 与测试 target。
2. 连接配置导入 JSON 最大16KiB，精确字段 `{schema_version:1,api_origin,media_origin,server_id,client_installation_id,token,expires_at}`。来自管理员明确生成的本机配置，不是公开登录协议；不接受未知/重复字段、空值、尾随 JSON。UUID 为小写v4，token为64位小写hex；expires_at是UTC RFC3339，必须仍有效且最多未来65分钟。生产配置与凭据不得进源码、fixture、日志、UserDefaults、URL或剪贴板自动复制。
3. API/media origin 均为 HTTPS origin：拒绝URL用户名/密码、query、fragment及非空路径（仅允许单个`/`并规范化移除）、无效端口。端点默认示例为 `https://airsim.eric3u.cc`，不是内置密钥或自动信任依据。修改origin/server/client即不同配置，不在原会话上换址。
4. token保存Keychain，service为`cc.eric3u.airsim.cloud.v2`，account由规范化api_origin+server_id+client_installation_id稳定编码；`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`、不同步、不共享给Watch。元数据可存UserDefaults独立`airsim.v2.*`命名空间；Keychain失败即不可连接，不降级明文存储。导入源文件不由App擅自删除；App不另留包含token的副本。
5. 请求前先无Bearer读取 `/.well-known/airsim`，严格验证version=2、profile=`airsim-v2-r4.1`、server_id、api_origin和media_origin与导入配置一致，能力telephony/messaging/experimental_audio匹配。设备origin只校验合法HTTPS元数据，App不访问mTLS设备端口。失败不向该服务发送token，不回退v1。
6. 配置身份使用 `(v2,api_origin,server_id,client_installation_id)`；每次启停/更换配置增加本地generation。所有异步结果须匹配捕获的配置身份与generation；过期/撤销401清理内存认证态、停止轮询/媒体、显示需重新导入，不自动签发或续期。

## M1 已冻结：HTTPS与类型

1. 独立注入式transport，生产使用ephemeral URLSession；无cookie/cache/磁盘缓存，拒绝全部HTTP重定向，系统TLS链/主机名/有效期验证、最低TLS1.2，禁用配置代理/PAC。禁止打印原始请求/响应、NSError带敏感URL或token、短信和号码。HTTP普通请求5秒deadline；用delegate或流式读取在接收时限制body，不能先无限data(for:)再检查长度。snapshot/modules/commands至多256KiB，messages至多2MiB，discovery/config至多16KiB。
2. 精确覆盖R4的discovery、modules、snapshot、messages、command receipts、media create/delete。模型依据R4及 `service/airsim/internal/control/model.go`、Agent control model，不发明字段。nullable snapshot/receipt与空backend_epoch等按真实服务协议处理，不能为兼容将错误必填值默认成有效状态。时间支持秒与RFC3339Nano；ID、计数、嵌套epoch与绑定不一致拒绝。多余响应字段按R4严格规则拒绝；若既有服务实际形状与文档冲突回报主控。
3. snapshot仅在online且observed_at年龄[-3秒,8秒]并且boot/backend/connection一致时可用；离线/旧快照只展示为旧状态，不准发控制。模块永远来自用户显式选择，不按最后心跳或第一在线模块自动替换。
4. 命令固定六字段：`command_id,agent_boot_id,backend_epoch,deadline,action,args`；外层`connection_epoch,command`。deadline45秒，UUID全小写。dial `{number}`；answer/hangup `{call_id}`；dtmf `{call_id,tones}`；sms.send `{number,text}`。**拒接incoming使用call.hangup，没有call.reject。** 号码`+?[0-9]{7,15}`，DTMF 1–16个`0-9A-D*#`，SMS 1–70 UTF-16码元、无NUL。
5. 每次用户动作仅POST一次，双击由进行中状态抑制。网络错误/5xx/收到响应前取消为结果未知，只能GET同command_id取收据，不再POST、不换command_id/模块/版本重试。HTTP 4xx明确拒绝单独呈现。receipt prepared/dispatched为等待，accepted/observed/failed/expired等保留原值；server completed不等于已接通或短信送达。接通/断开以同call_id实际snapshot确认。
6. 在请求发出前保存不含号码/正文/token的pending元数据（绑定身份、module、command_id、action、boot/backend、connection、generation/returned call_id若已知），用于进程重启后只读恢复。若POST结果丢失，先GET收据取得generation和call_id；未知期间不允许切换版本/服务/模块后重复动作。对查询失败保留unknown，不伪造成功。日志只稳定错误码与统计。
7. 初始/空闲前台1秒轮询选中模块snapshot/messages，目录5秒；同类请求单飞，错误退避1/2/4/8/15秒，成功恢复1秒。M1提供一次性API/纯状态机，不启动全局轮询，M2接入生命周期。非选中模块不自动占据音频或接听；界面需明确此轮只监控选中模块。
8. 通话上下文锁定 `(config,module,boot,backend,connection,call_id,generation)`，媒体/DTMF/挂断始终按上下文，不读UI当前选择。401/409/离线/epoch改变停止媒体并报告，禁止自动重新拨号或借另一client接管。仅拥有本client dial/answer成功所得generation可建媒体。

## M1 已冻结：ASMP与纯队列

1. WSS使用 `airsim.media.v2`，首个JSON为session_id/role=client/ticket，3秒认证、5秒paired；waiting/paired须匹配云端session_id与R4格式。票据只用于这一次连接，不放URL；断开只能用户显式请求创建新request/session，不能使用旧票据重连。
2. binary精确360字节：0..3 `ASMP`；4=1；5方向（发1/收2）；6..7 LE UInt16=40；8..23 UUID原始16字节；24..31 LE UInt64序号从1递增；32..35 LE UInt32=320；36..39=0；40..359为8kHz单声道S16LE的160样本。收到不匹配session/direction、保留位/长度错、零/重复/倒退序号即关闭；缺口计数，不伪装连续。纯codec有Swift与Go相同字节fixture。
3. 两方向均最多5帧，按单调到达/采集时刻记录帧龄，溢出丢最旧；出队丢弃>100ms帧，统计queue_drops。首帧后40ms预缓冲，固定20ms时间网格，不按实际唤醒时间累计；跳过迟到完整时槽，不追赶，实际输出间隔至少10ms。播放缺帧补零并单独计数；采集无输入不伪造样本，静音按钮可明确将有效采集帧置零。测试包括持续唤醒迟延不漂移、容量、过期、跳槽、迟到回调隔离。
4. UI/transport/audio需要的类型与纯队列在M1实现，真正WSS和AVAudioEngine连接在M3执行。未来引擎实际硬件采样率通过AVAudioConverter到8k，不能把首选采样率当真实格式。PCM永不落盘，最多保留有界内存及非内容统计。

## M2 主控补充裁决（M1完成审查后执行）

### 入口和兼容

- CloudVersionPreference存独立`airsim.cloud-version`，值v1/v2；另有显式完成选择标记。旧安装存在旧版App设置/first-connection/配对/推送配置证据则迁移为v1并保留全部旧配置；真正新安装先展示本地/v1/v2选择，在选择前不注册任一Relay或开始发现/权限提示。
- App入口创建无副作用的路由协调器；LegacyAppHost只在v1或明确本地模式时创建AppModel，CloudV2Host只创建独立v2 model。不能继续无条件`@StateObject AppModel()`，也不能让通知代理的stored cold handler初始化时偷偷启动发现。
- 现有本地/云端开关保留含义。非本地且已选择v2时使用v2界面（即使凭据未配置或云端关闭）；用户明确选择仅本地时回到原VoWLAN界面。v1配置和历史不删除，不自动改成v2。
- 两个界面的设置页都提供版本选择。选择变化先进入transitioning，校验旧runtime没有活动/振铃电话、媒体、在途或结果未知命令；存在则拒绝切换并解释需先结束/确认。不能仅依据UI是否有call卡片判断。服务地址/凭据/client/module切换同样受门槛限制。
- 旧runtime完成停止后再提交新选择并初始化新runtime；新服务验证失败保持v2未连接，不自动恢复v1。返回v1只能由用户再次选择。全部任务和迟到回调带runtime generation，不能把旧响应写进新UI或历史。

### v1停用与迟到事件

- R5确认现有v1 Worker没有注销接口且register禁止清空所有tokens。因此本轮**本安装的运行时/推送接收停用**与**远端注册删除**分开记录：不会发明注销API，不把本机停用宣称为远端删除，也不修改/部署旧Worker。
- 切换前停止并等待v1轮询、云状态、初始权限任务、metadata、注册重试、ActivityKit观察、VoWLAN discovery/探测、background standby、旧媒体以及Live Activity；hasStarted重置使显式切回能重新启动。取消后的注册/网络完成回调必须再次查generation和允许路由。
- 关闭本机PKPushRegistry desiredPushTypes/delegate并释放registry，unregisterForRemoteNotifications；停止本手机向Watch发布旧凭据/控制/媒体会话，拒绝本手机收到的Watch业务请求。不能删除Watch独立注册或远程挂断Watch现有通话，不能声称其他安装实例随之切换。
- 普通v1通知、导航、token回调、ColdLaunch handler、Live Activity动作在v2或未选择状态不得发旧控制、写v2历史或改变v2选择；完成回调必须调用。旧通知可清理本机对应待呈现请求，不能清理v2内容。
- 已在途且系统要求报告的v1 VoIP push仍需及时CallKit report incoming再report ended failed：使用单独隔离的过期通知处理对象，不启动旧网络/媒体、不接入v2 model、不执行用户旧CallKit动作。避免仅completion而漏掉系统报告。正常v1 active时原CallKit功能保持。M2对这条路径做注入测试，模拟器不冒充真机APNs到达验证。
- 本地可核验停止步骤均完成才允许新runtime控制；诊断保留`legacy_runtime_stopped=true, remote_registration_removal=unsupported`，界面不能显示“旧服务器注销成功”。这是R5对总体架构旧服务缺少注销API的阶段性细化；正式后台迁移还需远端注销与真机迟到推送验收。

### v2 前台界面、通话与短信

- 独立SwiftUI主界面沿用系统TabView风格，提供模块/拨号、短信、设置；当前模块明确显示短ID及在线/最近同步/实验音频状态，首次必须点击模块选择，不能自动选第一在线模块。来电仅监控明确选择的模块，显示号码/接听/拒接，拒接使用call.hangup。支持拨号、挂断、DTMF、静音、扬声器；不呈现未实现录音/呼叫保持/转移按钮。
- 设置包含v1/v2版本选择、HTTPS地址与服务身份、连接配置JSON文件导入（SwiftUI fileImporter）、到期时间/断开/更换连接、前台模式与后台来电不可用说明、实验音频显式开关（默认关闭）。校验配置/服务/鉴权完成才能控制；用户打开实验音频后允许在current configuration `experimental_audio:true`且audio.available的active managed call启动媒体，不能要求Agent voice_ready变true，也不能静默绕过实验开关。
- v2使用独立数据域，禁止旧HistoryStore写入。v2短信/通话历史按server+client+module+boot+backend+message/call ID隔离；当前协议没有sim_epoch，不伪造SIM一致性。最多2000条短信/500通话，受保护App文件、原子写入、exclude backup；内容只在本机显示，日志/验收产物不保存正文号码。历史来源/缺口需可辨，旧epoch不冒充当前收件箱。离线可看历史但不可控制。
- 列表支持短信发送及收到更新，sent显示已提交/已发送而非已送达；UTF16剩余字数和失败/未知状态可见。不能加服务不支持的删除模块短信/刷新modem等操作。状态变化以新的snapshot/messages替换与稳定ID合并，不能重复产生历史。
- 单个model串行处理业务动作。dial/answer返回generation后建立锁定上下文；若receipt先accepted但call_id尚未关联，只读同command继续等待，不能猜测call_id。恢复pending后只读重建owner上下文；缺少合法generation时禁止媒体/DTMF控制。对call.hangup先关闭本机媒体并发一个定向命令，持续只读确认断开，不把POST成功当挂断成功。
- v2本轮不用旧CallKit/PushKit或Watch，采用App内通话UI与独立AVAudioSession。失焦(.inactive)不等于后台，权限弹窗期间不自动挂断；真正进入.background时停止idle轮询，若本client有通话/媒体则停止媒体并提交一次定向hangup，保留未知结果待前台核对。UI明确本轮通话需保持App前台，不使用后台无声保活。网络失联仅停止媒体并保存context，不能盲目重拨/重发或自动换模块。
- 媒体断开时电话可能仍active，界面保留定向挂断，并提供明确的“恢复音频”用户动作：检查新鲜的相同owned call、创建新request/session/ticket，禁止自动旧票据重连。每次失败释放URLSession任务、engine/tap/player/queues和AVAudioSession。

M2验证应覆盖：旧安装v1默认、新安装无外联、v1→v2→v1、无效v2配置不回退、全部切换门槛、迟到snapshot/registration/push/Watch动作隔离、两模块和两client、离线/unknown不重发、短信历史分域、后台与权限弹窗差异。未支持的远端注销与APNs验证必须留在限制，不伪造通过。
