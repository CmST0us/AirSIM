# R7：原 App 视图与 v2 系统通话

2026-10-25。沿用 R4/R5 的身份、命令收据与媒体协议。本阶段将 ECS v2 接入原 App，保留本地、云端 v1、云端 v2 选择。通话质量优化暂缓。

## M1：共用原视图

- 所有版本使用 `RootView` 的拨号、最近、短信、联系人、设置五个标签及原 `ActiveCallView`。删除独立 `CloudV2Host` / 三标签产品入口。保留原导航、外观、联系人选择、`tel:` / `im:` 导航。
- `AppModel` 继续作为现有视图的数据与动作入口，组合可选 `CloudV2Model`。v2 初始化必须在旧 Watch、VoWLAN、旧云媒体及推送启动之前分支；不得为了呈现视图而启动旧运行时。v1/local 行为保持原路径。
- v2 状态投影到现有通话/短信展示模型，实际命令、持久化与媒体继续由 `CloudV2Model` 负责。历史 ID 保留服务、安装实例、模块与设备代次的隔离；显示模型不能反向决定控制目标。动作使用已有受验证的 binding/owned-call 和单次命令状态机。
- 原设备卡和选择器承载 v2 模块。导入配置、连接、模块选择与连接状态纳入原首次连接和设置视图。首次选择模块仍需用户显式选择，切换模块不得带入另一模块的历史、草稿或通话。
- 通话接听、拒接、挂断、静音、扬声器和 DTMF 从原界面进入 v2。静音/扬声器状态取实际 v2 媒体。录音及没有对应 v2 能力的维护操作不展示可点击的假入口；不向 v1 API 发送 v2 操作。
- 短信沿用列表、会话、撰写器和联系人入口，发送成功以命令终态为准，未知结果保留并显示待核对。刷新与清理通过模型动作，不允许视图直调旧 `model.api`。v2 清理仅清除当前服务/安装/模块的本地副本，不批量确认或删除模块短信。
- 连接、离线、未选模块、权限拒绝、凭据过期、未确认命令均给出中文状态与可执行恢复入口。内部 UUID、英文状态码和详细诊断移入诊断页，不作为主页面说明。
- M1 不宣称后台来电可用；后台/PushKit 由 M2 完成。原 v1 和 local 的设置仍可用，v2 不显示三星配对、v1 Relay 自检或 v1 录音入口。

## M2：PushKit、CallKit 与后台生命周期

- ECS 保存按服务/安装实例授权的 VoIP token、APNs 环境、允许的 Bundle ID 和当前模块订阅。只向未撤销、未过期且有模块授权的安装实例发送真实来电。注册、更新、注销与版本/服务/模块切换必须闭环。
- 来电 payload 明确标记协议 v2，携带服务、安装、模块、连接代次、Agent boot、backend epoch、call ID、稳定 CallKit UUID 与短有效期。不得携带认证凭据或媒体票据。v1/v2 分发依据 payload 与保存的身份，不能按当前开关重解释。
- 收到 VoIP push 后先及时向 CallKit 上报，再异步获取当前状态与处理业务。过期、已结束、旧版本或不匹配推送不能触发当前模块命令。重复事件复用通话身份；短信使用普通 APNs，不使用 VoIP push。
- iOS 冷启动从应用 delegate 建立当前运行时与 CallKit 处理器，不能依赖 SwiftUI 的 `onAppear`。CallKit 负责系统接听/挂断/静音/DTMF，v2 命令仍走已有收据、授权与定向控制。
- 普通进入后台不再挂断由本 App 管理的 v2 通话。闲置时停止轮询；来电唤醒及系统通话期间仅保留必要的状态与控制，音频由 CallKit 激活/停用驱动。后台授权只针对绑定的通话，不能泛化为任意后台拨号或发短信。
- 保留快照时效、设备代次、命令幂等和媒体票据限制。远端结束、撤销、网络失败及 provider reset 完成定向清理；不通过放宽时效或重发未知命令实现恢复。
- APNs topic 与签名 profile 一致。调试用 sandbox、发行用 production。密钥只存于部署受限文件；日志不输出 token、私钥、完整短信或号码。

服务端 HTTP 和 payload 的字段定义在 M2 实施前补充于本契约，由主控冻结。

## 验收与提交

M1 提交共用视图与原导航适配；M2 提交服务端推送和 iOS 系统通话；M3 提交设计/QA 反馈修复与回归证据。各里程碑使用明确路径暂存，不带入其他工作区改动。

QA 覆盖五标签、连接与模式切换、模块隔离、联系人/历史拨号、短信会话、权限/异常态、系统 URL、来电与系统动作、后台/冷启动和通知导航。模拟器和替身测试证明 UI/逻辑；真实 APNs、锁屏唤醒和硬件音频单独记录，不互相替代。设计和 QA 不做技术决策，问题交 iOS 执行会话，由主控定方案。

Apple 依据：[VoIP 通知处理](https://developer.apple.com/documentation/pushkit/responding-to-voip-notifications-from-pushkit)、[APNs 请求](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)。
