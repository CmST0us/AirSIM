# AirSIM v2 / R4 云端闭环契约

2026-10-24 主控冻结，协议标识 `airsim-v2-r4.1`。本阶段实现 RM500 → ECS → 受控前台测试客户端的 HTTPS/WSS 通话、短信、媒体闭环；不声称已经完成 iOS/Watch、APNs、浏览器安装器或正式账户登录。旧 v1 不修改、不自动回退。执行会话不能自行更改本文协议。

## 1. 共同约束

- UUID 均为小写 UUIDv4；时间为 UTC RFC3339Nano；计数为非负整数。严格拒绝重复/未知字段、尾随 JSON、错误类型、空值代替必填值。公共错误 `{"error":"stable_code"}`，不回显输入、证书、令牌、号码或正文。
- `server_id`、`user_id`、`client_installation_id`、`module_id` 相互独立。设备使用现有 Ed25519 身份，不复制私钥到主机/服务器。普通客户端不能上报设备状态；设备不能提交用户动作。
- 仅 HTTPS/WSS；TLS>=1.2，正常主机名、链、有效期验证，不允许 insecure skip、自动重定向、URL 凭据、URL token。自动代理默认禁用。配置的三个 origin 必须是 HTTPS origin（允许显式端口），路径固定；WSS 仅将 scheme 换为 wss。
- Go 标准库 HTTP/TLS/x509；WebSocket 统一固定 `github.com/coder/websocket v1.8.15`，禁用压缩，单 reader/串行 writer。服务 PostgreSQL 驱动固定 `github.com/jackc/pgx/v5 v5.7.6`。工具链沿用已验证 Go 1.24.13、CGO=0。若版本实际不能取得/要求不同工具链，报告主控，不静默换版本。
- 身份、控制收据持久化；PCM 永不落盘。R4 的短信正文、号码和实际状态快照只在有界内存与受保护传输中流转，数据库不保存正文/号码/原始命令。日志仅稳定错误码、无敏感元数据。

## 2. R4 受控引导与证书

产品登录/浏览器激活仍按总体架构后续实施。R4 采用明确标记的管理员本机引导，不新增公网管理员/匿名注册接口：`airsim-admin` 只通过受保护的 ECS shell/Compose 一次性任务使用数据库及设备 CA。控制/媒体常驻进程不持有设备 CA 私钥。

管理员初始化随机 server_id、唯一 owner user_id、Ed25519 设备 CA（5 年 CA 有效期），另生成彼此独立的 edge bearer 32 bytes、media 内部 bearer 32 bytes 及命令摘要 HMAC key 32 bytes。文件在仓库外 0700 目录/0600 文件，绝不默认打印秘密。生成一次性测试 client_installation_id、随机 32-byte token（小写 hex，服务端只存 SHA256）、60 分钟有效期；输出至显式 0600 文件。可撤销、可重新签发；不称作正式登录或 refresh 流程。

本机 Agent 新增以下 0600 Unix API（不暴露网络）：

1. `POST /v2/local/cloud/prepare`，body 精确字段 `{request_id,server_id,api_origin,device_origin,media_origin,device_ca_pem,server_ca_pem,nonce,expires_at}`。nonce 为 32-byte lowercase hex；server_ca_pem 可为空字符串表示系统根，否则只用显式 PEM 根；expires_at 在未来 10 分钟内。幂等同 request_id 同内容；其他 pending 冲突 409，禁止覆盖已激活的不同 server_id/端点。保存完整 pending 原子 0600 并 fsync；返回 `{request_id,module_id,public_key_base64,csr_pem,proof_base64}`。CSR 使用原设备 Ed25519 key，CN=module_id，URI SAN=`urn:airsim:<server_id>:module:<module_id>`；仅导出 crypto.Signer 封装、公钥和 CSR，不导出 key/seed。
2. proof 签名字节为 UTF-8：`airsim-v2-r4-provision\n` 后依次追加 `request_id,server_id,module_id,api_origin,device_origin,media_origin,nonce,expires_at,sha256(csr DER)`，每项独占一行且结尾有 LF。所有 ID/origin/时间禁止换行，CSR hash 小写 hex。公钥严格 base64；CSR 自签名/public key/SAN 必须与 proof 和 module_id 一致。
3. 管理员 `issue-module` 读 prepare request + response 文件，校验 expiry、proof、CSR、公钥，并要求 request 的 server_id 与三个 origin 精确等于服务部署配置；不接受任意请求自带端点。DB 事务按 request_id 幂等登记 module→owner，不允许覆盖另一 owner、公钥或 server；签发 ClientAuth-only 30 天设备证书，SAN 如上。证书及登记状态持久化，同事务重试取回同一证书。输出激活 bundle `{request_id,server_id,module_id,certificate_pem,receipt_base64}`。receipt 由设备 CA Ed25519 key 对 `airsim-v2-r4-commit\n` + `request_id,server_id,module_id,sha256(certificate DER),nonce` 各一行含尾 LF 签名。CA 信任来自先前经本机 owner 设置的 pending，bundle 不能替换根或端点。
4. `POST /v2/local/cloud/activate` 接受上述 bundle，校验 pending、CA签名、证书链/时效/ClientAuth、设备公钥、唯一SAN及 receipt 后原子保存 config；pending 可在成功后清理，崩溃重试返回同一结果。保存失败不能宣称激活。相同激活幂等，禁止换服务。私钥仅既有 identity.json。后台开始连云端，不重启设备/厂商服务。
5. `GET /v2/local/cloud` 返回 configured、connected、server_id、module_id、connection_epoch、last_connected_at、last_error、证书到期，不返回凭据。`--cloud-config` 可指定该安全配置文件，默认 data/config/cloud.json；不存在时保持纯 R3 行为。明确识别损坏/权限错误，不自动抹除身份。
6. `GET /v2/local/cloud/media-stats` 仅在原有受保护 Unix API 提供当前或最后一次云端桥统计：精确字段 `{session_id,state,reason,cloud_input_gaps,local_input_gaps,queue_drops,zero_frames}`。state 为 idle/starting/streaming/closed，初始 session_id/reason 为空且计数为0；新桥开始时归零，关闭后保留最后一次统计。无票据/PCM，不抢读 R3 AudioEvents；这些计数与 helper 原生 PCM 统计分开，不改变媒体线上帧格式。

R4 暂不自动续期；证书到期前记录状态，过期 fail closed，管理员通过同一持有证明重新签发的流程由后续主控另行冻结。不得称为永久生产激活完成。

## 3. Edge 与设备认证

- API/media 使用普通 TLS 域名；设备控制使用独立 mTLS SNI 域名。Caddy 校验设备 CA+ClientAuth；覆盖 `X-AirSIM-Client-Cert` 为已验证客户端 leaf DER 的 base64，覆盖 `X-AirSIM-Edge-Token` 为仓库外共享 edge bearer；API/media 路由删除这两个头。control 再校验 bearer、leaf 链、有效期、SAN、公钥/序列号与未撤销 DB module。缺少任何一项拒绝，绝不单凭 body.module_id 或 header CN 认证。
- `/.well-known/airsim` 返回 `{protocol_version:2,profile:"airsim-v2-r4.1",server_id,api_origin,device_origin,media_origin,capabilities:{controlled_test_client:true,telephony:true,messaging:true,experimental_audio:true,apns:false,interactive_login:false}}`。Agent 首次连接前从已配置 API 获取，完整核对三个 origin/server_id/profile，禁止跟随新端点。
- edge/control/media/postgres 网络彼此按需要连接；所有内部端口不发布公网；媒体内部 API 另要求 32-byte bearer（不与 edge bearer/客户端 token 混用）。主机健康检查不回显凭据。

## 4. 控制 WSS

固定设备路径 `/v2/device/control`，subprotocol `airsim.control.v2`，仅设备 mTLS。每连接消息上限 131072 bytes，发送队列 32 项，写超时 3 秒；满则关闭连接，不能静默丢命令。应用 heartbeat 每 5 秒，15 秒没收到有效 frame 关闭；握手 5 秒。断线指数退避 1/2/4/8/16/30 秒加最多20% jitter；每模块只允许一个活动连接，新认证连接替代旧连接并撤销旧媒体。

所有文本消息通用结构 `{type,protocol_version:2,module_id,connection_epoch,sequence,payload}`，字段固定。sequence 在各方向从1严格递增；hello 的 connection_epoch 为空，其他必须匹配服务端发放 UUID。已失效连接的迟到消息一律不更新状态/收据。

| type | 方向 | payload 精确字段与含义 |
| --- | --- | --- |
| hello | Agent→server，首帧 | `{agent_boot_id,backend_epoch,agent_version}`；backend_epoch 可空表示未ready；module_id须匹配证书 |
| welcome | server→Agent，首帧 | `{server_id,heartbeat_seconds:5}`；外层connection_epoch为新UUID |
| heartbeat | 双向 | `{}`；仍计入sequence |
| snapshot | Agent→server | `{agent_boot_id,backend_epoch,observed_at,control,calls,audio}`；嵌套使用 R2 Status/CallsView、R3 audio Status，audio清除token/socket等无关字段。每秒读取，变化即发，最长5秒强制发；全量替换，无“漏事件仍假装最新” |
| messages | Agent→server | `{agent_boot_id,backend_epoch,observed_at,inbox_gap,inbox_dropped,messages}`；分批最多32条，每帧最多64KiB。每秒检查变化，首次/重连发送当前内存收件箱；已见 message_id 更新而非新增重复。不宣称运营商重复短信已去重 |
| command | server→Agent | `{client_installation_id,generation,command}`；command 精确沿用 R2 Request 六字段，必须重新经 control.Parse 再 Submit。generation 为 UUID，SMS也使用独立请求generation |
| receipt | Agent→server | `{command_id,status_code,receipt}`；receipt 为 R2 回执或 null（无body错误）。接受后每250ms查询未终态回执，变化即发送，最多64项；不能把HTTP202当实际成功。accepted 对 dial/dtmf/sms 即结束主动轮询，answer/hangup 最多再观察11秒，之后释放 pending 槽但不篡改真实回执；后续 receipt_query 仍只读 journal |
| receipt_query | server→Agent | `{command_id}`；只读现有journal，绝不再Submit |
| media_start | server→Agent | `{request_id,session_id,call_id,agent_boot_id,backend_epoch,client_installation_id,generation,ticket,expires_at}`；固定媒体URL由配置决定 |
| media_status | Agent→server | `{session_id,state,reason}`；state=starting/streaming/closed；不传本机token |
| media_stop | server→Agent | `{session_id,reason}`；只能停止匹配的云端 session |

首次 snapshot 至少完整读取 control/calls 两次验证 boot/epoch 没变；不一致不发假拼接快照。call状态每秒内上报；本地R3资格事件仍由原 manager 独占消费，云端不抢 AudioEvents channel。后台只读轮询调用有界超时。

断连：立即取消本连接媒体，停止接受旧connection_epoch命令；已提交 HAL 的动作不重发、不自动挂断电话。未确认结果为 unknown；server重连只允许 receipt_query 取收据，不自动再次投递 command。短信正文不打印、不记录在验收元数据，消息列表仅账户所有者可读。

## 5. 客户端 API 与命令所有权

Authorization: Bearer <随机客户端token>；服务端检查 user/client有效性及token时效/撤销。只接受 JSON，命令 body<=8192，普通读写总 deadline<=5秒。不以 query参数认证。R4 前台验收客户端使用 HTTPS 轮询（1秒），不新增客户端WSS游标/后台唤醒承诺。

| 路径 | 方法与body | 返回 |
| --- | --- | --- |
| `/v2/modules` | GET | `{server_id,modules:[{module_id,online,last_seen,agent_boot_id,backend_epoch,connection_epoch}]}`，仅所属模块 |
| `/v2/modules/{module_id}/snapshot` | GET | `{server_id,module_id,online,last_seen,connection_epoch,snapshot}`；离线明确false，保留最后快照但不标fresh |
| `/v2/modules/{module_id}/messages` | GET | `{server_id,module_id,agent_boot_id,backend_epoch,online,inbox_gap,inbox_dropped,messages}`；按module+boot+epoch+message_id隔离，最多128条/1MiB，旧epoch留gap说明不混入当前 |
| `/v2/modules/{module_id}/commands` | POST `{connection_epoch,command}` | 新建202 `{command_id,state:"pending",generation,receipt:null}`；重复同请求200现有记录，冲突409；目标离线503，不离线排队 |
| `/v2/modules/{module_id}/commands/{command_id}` | GET | `{command_id,state,generation,receipt}`；state=pending/dispatched/completed/outcome_unknown，receipt保留R2实际状态 |
| `/v2/modules/{module_id}/calls/{call_id}/media-sessions` | POST `{request_id,connection_epoch,generation}` | 201 `{session_id,ticket,expires_at,media_url,format}`；同活动request_id返回同一结果200，关闭后410，冲突409 |
| `/v2/modules/{module_id}/calls/{call_id}/media-sessions/{session_id}` | DELETE | 204仅当前客户端所拥有目标，其他目标404；不隐式挂断 |

命令 command 原样沿用 R2，包括 caller提供的expected boot/backend epoch、UUID command_id、deadline<=60秒。服务器再次校验并绑定 module_id/user/client/connection_epoch。数据库用全局command_id唯一约束及完整请求HMAC（包含上述绑定）实现幂等；不存号码/文本。先持久化记录再发一次，发送前标dispatched；网络/进程失败不能自动重发。POST原请求冲突/重复检查先于current epoch检查，使已存在请求能得到原收据。不同用户不能探测他人command_id。

每模块通话控制 reservation 存 PostgreSQL，按module行锁串行化：dial 在空闲快照且无reservation时获得 client+generation；answer/拒接(incoming hangup)在目标incoming且无owner时取得。call_id由Agent回执关联并不可换绑。已绑定通话的hangup/dtmf/media必须同client、同generation与当前boot/epoch；非拥有者409。SMS不抢通话reservation。snapshot确认目标disconnected才释放；断线/结果未知不能把同一通话交给其他client，owner可以重连查询并明确挂断；新的控制连接撤销旧媒体，但不会自动重建。

本机 Unix API 在 R4 仍是 root 管理入口，允许明确的本地维护；不把它宣称为普通App配对接口。云端媒体必须经server ownership和Agent实际唯一managed active资格双重校验；已有本地媒体busy时云端返回失败，禁止抢占。来自服务器的media_start还须匹配Agent已见的本次云端call/client/generation（在本次云端成功dial/answer的receipt中记录），不能借可信连接接管另一通话。

数据库只存账户/模块/证书/测试客户端token hash/command收据元数据/call reservation。在线快照、短信、媒体票据及待发payload只在有界内存。重启将未终态dispatched标outcome_unknown；恢复snapshot前不接受动作，不能把数据库中的旧在线状态当真。每账户最多16模块/16测试client、每模块最多32pendingcommands；命令表本阶段最多10000记录，满时拒绝，不能删除仍有副作用风险的去重记录来腾位置。

服务端 command.state 与实际 R2 receipt.state 分开：R2 prepared/dispatched 对应 dispatched，accepted/observed/failed/expired 对应 completed，outcome_unknown 对应 outcome_unknown。保留 receipt 原值，accepted 不表示电话已接通或短信送达；业务结果另看实际 calls/messages。accepted→observed 的后续回执仍可更新同一记录，禁止凭空生成 R2 不支持的 completed/rejected 回执状态。

媒体 request_id 幂等历史在单次 control 进程生命周期内最多10000项（含已关闭），达到上限拒绝新 request_id 为429，已有 request_id 仍返回原幂等结果；关闭立即清空明文票据，只保留绑定元数据。重启不恢复媒体 session，不宣称跨重启媒体幂等。内部媒体网络请求不得持有全局控制互斥锁等待，慢媒体不得阻塞其他模块快照、心跳及命令处理。

## 6. 独立媒体 WSS

固定 `/v2/media`，subprotocol `airsim.media.v2`，首帧文本JSON<=2048：`{session_id,role,ticket}`，role=agent/client。3秒内鉴权，失败关闭。一次性随机32-byte hex ticket绑定role和完整会话，存储时hash；创建时控制服务只在内存保留必要返回值。票据30秒到期；Agent 对未来时间的合理性检查允许最多5秒设备时钟偏差，即单次采样 `now` 后要求 `0 < expires_at-now <= 35秒`，不改写绝对 `expires_at`，服务端仍严格执行原30秒到期。session双方须5秒内配对；任意角色一次使用，断线后不能拿旧票据重连。

鉴权成功回复文本 `{"type":"waiting","session_id":...}`；双方存在后各发 `{"type":"paired","session_id":...,"format":{"sample_rate":8000,"channels":1,"sample_format":"s16le","frame_samples":160}}`，随后只允许 binary。

每 binary message 恰好一个360-byte R3 ASMP帧，session UUID使用云端session_id；client→agent direction1，agent→client direction2；sequence从1递增，允许计数的跳跃，拒绝倒退/重复。格式固定8k monoS16LE160 samples；媒体服务不解码/混音/重采样。每方向队列最多5帧，丢最旧完整帧并计数，单次write100ms，2秒无合法frame关闭双方，最大30分钟。32个活动session全局硬限额，每模块/每客户端1个；慢握手最多32，不能无限goroutine。

Agent复用R3 media.Manager及0600 Unix媒体入口，不更改C helper。云端paired后创建本地会话并完成本地认证；转换ASMP的session UUID与独立序号映射，PCM payload原样；分别统计云端输入序号缺口、本机序号缺口、桥队列丢帧及补零，不能因重新编号掩盖网络缺口。桥接的两个方向分别使用最多5帧的有界队列，溢出丢最旧完整帧并计入queue_drops；入队时记录单调时钟，发送前丢弃年龄超过100ms的帧并计数。每方向在首个真实帧入队40ms后开始，以20ms节拍最多输出一帧，不按突发到达速度直接转发，不追赶积压的tick。发送时钟锁定首个真实帧入队40ms后的固定20ms网格，避免每次唤醒误差累计为采样时钟漂移。每个时槽最多一次输出；唤醒已落后一个完整时槽，或write完成时已错过下一目标，则跳至严格晚于当前时刻的下一个网格点，不补发遗漏时槽。相邻真实输出起点至少间隔10ms；不足时跳过当前时槽，仍保持原网格。云端→本机队列为空时输出一帧零PCM并计入zero_frames；本机→云端为空时跳过该tick，不伪造采集帧。补零不续约真实输入的2秒超时，原来的100ms write及全部鉴权/lease限制不变。PCM payload除明确补零外原样，不改C helper、采样率或帧格式。下行本地EOF、helper退出、lease丢失、云端任意I/O错误立即关闭整条桥并上报media_status。创建/配对/本地绑定总deadline5秒，失败回收，无自动重连/重拨。控制EOF主动停止本连接云端媒体但不能停止另一个本地媒体session。

control→media内部HTTP仅Docker内网+独立bearer：
- POST `/internal/sessions` body `{session_id,module_id,call_id,agent_boot_id,backend_epoch,connection_epoch,client_installation_id,generation,agent_ticket_hash,client_ticket_hash,expires_at}`，201，冲突409；内部body<=4096。
- POST `/internal/sessions/{id}/renew` body `{connection_epoch,generation}`，204；每秒续租，3秒未续租fail closed。
- DELETE `/internal/sessions/{id}`，204；撤销关闭两个socket并删除票据，幂等。
- GET `/internal/sessions/{id}` 返回脱敏统计/state/reason；无token/PCM。

control只为仍在线、同owner代次且真实active通话续租；mediaStart在control持有reservation锁内产生，只发一次。控制断连、snapshot非active、客户端撤销、期限结束及时DELETE并停止续租。两容器重启都明确中断媒体，恢复必须新request/session/tickets。

## 7. 验收及发布边界

先做两模块/两客户端模拟集成，验证错误证书/未知模块/伪造身份头、跨module命令、旧epoch、重复ID、离线不排队、媒体票据复用、两客户端争用、慢消费者、断线/容器故障回收与DB恢复。再用真实ECS TLS/数据库与RM500独立出站网络，执行授权号码的拨号、入站接听/拒接、SMS双向、75秒双向内容确认及定向挂断。主控独占设备与真实呼叫，不让两个执行会话同时操作模块。

R3 `voice_ready=false` 暂不改；R4通过前仅显式实验音频能力。授权测试客户端可显式使用 experimental_audio，但不得改成全平台语音已就绪。手机后台/APNs/iOS v2选择器留在后续App阶段，不能把本阶段受控云端测试客户端宣称为App已完成。
